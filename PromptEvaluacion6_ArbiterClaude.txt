T1. ACQUISITION CONFIRMATION

T2. BLOCKER FIX VALIDATION (your T4-F1 specifically)

  The runtime now binds `_lastGesturePath = e.composedPath()` and
  `_readGestureAttested(forElement)` verifies forElement is in
  that path. Validate:

  T2.1 Is the composedPath capture correct under SHADOW DOM
       click delegation? When user clicks an element inside an
       open shadow root, e.target points to the shadow host
       (per browser policy). composedPath() returns the full
       path including shadow descendants. Does the runtime walk
       composedPath BEFORE the browser retargets? Reference
       js/nac-v2-extensions.js:_captureGestureFromDom.

  T2.2 Is GESTURE_FRESH_MS = 16 too tight for legitimate cases?
       Real click-to-handler latency on mid-tier mobile is
       typically 1-5ms. 16ms covers 1 frame; promise-resolved-
       later handlers (legitimate async work after a click)
       lose attestation. Is this the desired behaviour or too
       strict?

  T2.3 Edge case: keyboard navigation. User presses Enter on a
       focused button. The keydown event fires; default behaviour
       fires a click on the focused element. Does the keydown's
       composedPath include the button? If not, the button's
       NAC.invoke() will fail user_gesture_path_mismatch despite
       legitimate keyboard activation.

  T2.4 Edge case: programmatic focus + Enter. Tab key navigates
       focus, Enter triggers click. The keydown is genuinely
       user-trusted, but its target is the previously-focused
       element. Does the chain hold?

  T2.5 New finding `user_gesture_path_mismatch` -- is the error
       code descriptive enough? Will a debugging adopter grok
       why their event was rejected?

  T2.6 Verify the spec text in sec 15.10 (the annex Claude
       wrote in Round 3) matches the runtime behaviour. Any
       mismatch is a finding.

T7. NEW REGRESSIONS CHECK (rc3 introduced)

  rc3 added ~600 LOC. Specifically check:

  T7.1 Does `set_provenance_secret` now block on the warm-up
       sign call (which is async)? If so, secret rotation in a
       hot path can introduce latency. Reference
       js/nac-v2-extensions.js:set_provenance_secret.

  T7.2 Does `bridgeIframe` HMAC verification on handshake_ack
       fail OPEN (allow without verification when no secret
       registered) or fail CLOSED (reject without secret)?
       Both have security trade-offs; pick one.

  T7.3 Does `autoRegister.watch` chunked flush preserve order?
       Some adopters may rely on registration order to derive
       UI sequence. requestIdleCallback runs at idle time,
       which can interleave between sub-batches.

  T7.4 The new `_intermediateScopes` index grows monotonically.
       There is no GC. A long-running app that creates and
       discards scopes will leak. Memory-leak finding?

  T7.5 The new `_bridgedShadowHosts` WeakSet cleans up when
       hosts are GC'd. Verify this is actually a WeakSet (not
       Set) in the runtime so dead hosts don't leak.

  T7.6 The new finding code list is 4 entries longer (
       user_gesture_path_mismatch, agent_attested_without_os_level,
       adopt_blocked, adopt_derive_slow). Check that the
       conformance suite covers each.
