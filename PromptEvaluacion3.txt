### Before you start: who this is actually for

NAC is described in technical terms (HTML attributes, JSON
manifest, JavaScript runtime, event contract). That framing
is correct but incomplete. The downstream beneficiary of
every NAC primitive is, more often than not, a human with a
disability whose access to the UI depends on assistive
technology that NEEDS a stable, machine-readable contract:

- People with motor disabilities (limited dexterity, tremor,
  paralysis, RSI) who operate UIs through voice control
  software (Talon, Voice Access, Dragon, browser voice modes).
  Their tools collapse on UIs without stable semantic IDs.
  NAC's data-nac-id + label_i18n is exactly that contract.
- People with visual disabilities (blindness, low vision,
  dyschromatopsia) whose screen readers consume ARIA but
  benefit from NAC.describe()'s richer manifest-grade
  introspection.
- People with cognitive disabilities, chronic illness, ADHD,
  executive-function variation, autism spectrum, who delegate
  multi-step UI work to AI assistants when they cannot
  navigate alone. NAC's agentic loop pattern (sec 9.1, 9.2)
  makes that delegation auditable.
- People whose capabilities vary day-to-day (chronic pain,
  medication side effects, mental health). On a hard day,
  the same person who navigates fluently on a good day can
  delegate the work and not lose access to the system.

The cost of a sloppy contract is not a CI failure. It is a
user locked out of a system they need.

The PHILOSOPHY.md section "What NAC does for people with
disabilities" develops this in depth. **Please read it
before you start your review** -- the technical evaluation
that follows means more when you carry the stakes. Treat
the engineering critique as seriously as you would for any
other spec, and add a layer that asks: does this contract
actually deliver on the promise to those humans?

### What changed since v1.7.0 (the v1.8 incorporations)

v1.8.0 lands every action item the four-AI peer review of
v1.7.0 (Microsoft Copilot, DeepSeek, Mistral Le Chat, Grok)
agreed on. Strict superset of v1.7.0 -- every v1.7 plugin
remains valid; the new primitives are additive and opt-in.

1. **ProvenanceBlock on every event** (spec sec 6.2.1).
   Every nac:* event detail now carries
   `source: { type: 'user' | 'agent' | 'script', id?, tool? }`.
   The runtime defaults to {type:'script'} when no caller
   sets it. AI agents and voice tools MUST set
   {type:'agent', tool:'...'} so audit pipelines can
   distinguish human from automated traffic. This was the
   Copilot + DeepSeek + Grok action item: silent failure was
   not the only audit gap, lack of provenance was the deeper
   one.

2. **Command events: nac:command:rejected and
   nac:command:failed** (spec sec 6.2.30, NEW). The runtime
   emits these from NAC.click / fill / drag_drop when:
   rejected = preflight detected (target disabled, hidden,
              not_found, ambiguous, role_mismatch,
              drag_type_mismatch).
   failed   = unexpected throw during execution.
   Public helpers NAC.command_rejected() and
   NAC.command_failed() let plugin authors surface their own
   preflight rejections + execution failures with the same
   wire shape. This was DeepSeek's "AI claims success based
   on event emission while the UI silently ignored the
   command" finding.

3. **data-nac-validate="skip"** declarative attribute (spec
   sec 3.1, NEW). Marks a third-party-widget subtree as out
   of scope for NAC-3 hard-error gating. The validator does
   NOT raise drift / missing-required findings on the subtree
   but DOES emit a structured warning if the region contains
   operable surface ([data-nac-id] elements or interactive
   native controls). This was the brownfield-abandonment
   escape hatch DeepSeek + Copilot + Mistral all asked for.

4. **data-nac-a11y-hint** declarative attribute (spec sec 3.1,
   NEW). Pipe-separated semantic tags declaring what voice
   tools, screen readers and AI agents should warn about
   BEFORE invoking the action. Recognised vocabulary:
   irreversible | requires_confirmation | dangerous |
   long_running | costly | external_side_effect | data_loss.
   The runtime parses these into an array on
   NAC.describe()/find() output. Plugin manifests can read
   them. Mistral's specific recommendation for cognitive
   disability + irreversible-action interposition.

5. **Drag-drop type validation** (spec sec 13.4 v1.8
   addition). data-nac-drag-type on source +
   data-nac-drag-accept (CSV or "*") on target. Mismatch
   rejects with NacError('drag_type_mismatch') AND emits
   nac:command:rejected with reason='drag_type_mismatch'.
   Closes DeepSeek's finding that drag_drop did not validate
   operation kind (reorder vs move vs copy).

6. **Migration helpers** (spec sec 13.9, NEW).
   - NAC.emit_dual(canonical, legacy, detail) fires both
     names with the same detail, canonical first
     synchronously, same task tick.
   - NAC.command_rejected(detail) and NAC.command_failed(detail)
     public wrappers around the internal emitters.
   - NAC.check_canonical_shape(eventType, detail) -> {ok,
     missing[]} pure utility that asserts a detail satisfies
     the required canonical fields per sec 6.2.
   - NAC.validate_event_conformance(driver, opts) -> Promise.
     Runtime equivalent of the v1.7 demo's "event conformance"
     self-test, now part of the contract per Mistral's
     specific recommendation. The self-test is now a
     NAC-3 normative requirement (sec 6.2.27).
   Plus tools/migrate-legacy-events.js: a Node 14+ codemod,
   no external deps, that walks a project tree and rewrites
   detail.<legacy> reads to detail.<canonical> with a
   fallback (or with --strict drops the fallback).
   docs/MIGRATION_v1_to_v2.md is the user-facing migration
   guide for the v2.0 hard-break.

7. **Public CSS custom properties** (spec sec 7.6, NEW).
   --nac-focus-pulse-color, --nac-focus-pulse-duration,
   --nac-focus-pulse-thickness, --nac-focus-pulse-intensity,
   --nac-focus-pulse-glow-radius, --nac-section-visited-color,
   --nac-section-visited-duration. Hosts targeting users with
   ADHD, attention or chronic-pain variability can crank the
   cue salience without forking. prefers-reduced-motion
   respect is normative. Mistral + Grok action item.

8. **Stable persistent IDs for paginated/virtualized
   collections** (spec sec 6.2.31, NEW). Canonical id fields
   on collection events MUST be stable across pagination and
   virtualization. Voice control + AI delegation collapse on
   virtualized 5000-row autocompletes when "pick Berlin" is
   mapped to "click position 437" rather than "click
   option_id=opt-de-berlin". Grok + DeepSeek action item.

Quality-of-life additions tied to the above:
- legacy_event_field warning is now deduplicated by
  (event_type, field) per session (DeepSeek's "400 identical
  warnings per single user action" finding).
- skip_subtree_contains_interactives validator finding
  (severity warn) when a skip region contains operable surface.
- Demo gained 3 cards (skip-validate region; dangerous
  action with a11y_hint; drag-types accept/reject) plus the
  v1.7 conformance self-test was extended to assert
  canonical shape on the new command events.

### Style requests

- Be specific. Cite section numbers and line ranges.
- Include both strengths and limitations. Limitations are
  especially useful. Generic praise is not.
- Where you are uncertain, say so rather than guessing.
- Reply in English so multiple AI reviews can be compared.
- Stay under 2800 words total (T7, T8, T9, T10 need
  headroom).
- T10 in particular: ground your answer in concrete
  primitives from the spec. "It helps disabled people because
  it's accessible" is not a useful sentence; "Sec 3.1
  data-nac-a11y-hint=\"irreversible\" lets a screen reader
  warn a user with cognitive disability before the AI
  invokes a delete that cannot be undone" is.
