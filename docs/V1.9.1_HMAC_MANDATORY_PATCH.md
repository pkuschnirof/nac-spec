# v1.9.1 patch draft -- HMAC mandatory at NAC-3 for agent-sourced events

**Status**: DRAFT, awaiting Pablo's approval.
**Trigger**: Claude arbiter (closing v1.9 review, 2026-05-08) identified this as the single substantive recommendation that should land before v2.0 announce.
**Scope**: 1 normative spec line + 2 runtime code paths + 1 CHANGELOG entry. **No breaking change** to plugin code; the breaking change is to PIPELINES that accept agent events, which now must verify signature.
**Estimated implementation time**: 2-3h Sumi + 30min Pablo review.

---

## Why

> *"An audit pipeline that accepts unsigned `source: { type: 'agent' }` is back to where it started... For users in regulated environments (healthcare, finance, legal -- exactly the populations the new `audit_required` hint serves), this is the gap that swallows the rest of the work."*
>
> -- Claude arbiter, NAC v1.9 closing pass, 2026-05-08

v1.9 ships `NAC.sign_provenance(detail, secret)` + `NAC.verify_provenance(detail, secret)` (HMAC-SHA256 + constant-time compare) per sec 6.2.1, BUT keeps signing OPTIONAL at NAC-3. Result: a misbehaving or compromised emitter can claim `source: { type: 'agent', tool: 'claude' }` without proof, and the audit pipeline cannot distinguish forged provenance from real provenance. The `audit_required` hint (v1.9 sec 3.1) is hollow until verification is enforced.

v1.9.1 promotes signing to mandatory for `source.type === 'agent'` events at NAC-3. NAC-2 and NAC-1 stay unchanged (optional).

## The exact spec change (one line)

**File**: `spec/NAC-v1.0.md`, sec 6.2.27 ("Validator behaviour at NAC-3"), in the "ProvenanceBlock enforcement" subsection (lines ~2106-2120).

**Add new paragraph after the existing ProvenanceBlock enforcement subsection**:

```markdown
#### Agent-source HMAC enforcement (REQUIRED at NAC-3, v1.9.1+)

`validate_event_conformance` MUST verify that every captured
event detail with `source.type === 'agent'` carries a
`source.signature` field that successfully validates against
the host's registered HMAC secret via
`NAC.verify_provenance(detail, secret)` returning `true`.
Events with `source.type === 'agent'` AND missing or invalid
signature are counted as failures (severity `error` at NAC-3).

The runtime helper `check_canonical_shape(eventType, detail)`
MUST also return `ok: false` when `detail.source.type === 'agent'`
AND `detail.source.signature` is absent OR fails verification
against the registered secret.

This requirement closes the gap the v1.9 closing arbiter
flagged: an audit pipeline accepting unsigned agent events
cannot distinguish forged provenance from real provenance,
making the v1.9 `audit_required` hint hollow for users in
regulated environments (healthcare, finance, legal).

The HMAC secret is registered via
`NAC.set_provenance_secret(secret)` (new in v1.9.1). Hosts
SHOULD source the secret from a server-rendered template OR
from a per-user vault; SHOULD NOT bake it into static JS.
The secret rotates per-deployment OR per-tenant; the
verification helper accepts a list of secrets so rotation
overlaps do not break in-flight events.

NAC-2 and NAC-1 keep signing OPTIONAL. Only NAC-3 enforces.
```

## Runtime code changes

### `js/nac.js` change 1 -- add secret registration helper

**Location**: near `sign_provenance` and `verify_provenance` declarations (sec related to v1.9.0 helpers).

```javascript
/* v1.9.1: registered HMAC secret(s) for verifying source.signature
   at NAC-3 enforcement. Multiple secrets supported so per-deployment
   rotation works without a hot cutover. The runtime tries each
   secret in order; first match wins. */
let _provenanceSecrets = [];

function set_provenance_secret(secretOrSecrets) {
  if (typeof secretOrSecrets === 'string') {
    _provenanceSecrets = [secretOrSecrets];
  } else if (Array.isArray(secretOrSecrets)) {
    _provenanceSecrets = secretOrSecrets.slice();
  } else if (secretOrSecrets == null) {
    _provenanceSecrets = [];
  } else {
    throw new NacError('invalid_argument',
      'set_provenance_secret expects string or string[]');
  }
}

async function verify_provenance_with_registered(detail) {
  if (!_provenanceSecrets.length) return false;
  for (let i = 0; i < _provenanceSecrets.length; i++) {
    if (await verify_provenance(detail, _provenanceSecrets[i])) {
      return true;
    }
  }
  return false;
}
```

Add `set_provenance_secret: set_provenance_secret` to the global.NAC export.

### `js/nac.js` change 2 -- enforce in `check_canonical_shape`

**Location**: existing `check_canonical_shape(eventType, detail)` body, after the v1.9.0 source.type check.

```javascript
async function check_canonical_shape(eventType, detail) {
  // ... existing v1.9 source.type check ...

  /* v1.9.1: agent-source signature enforcement at NAC-3.
     If the runtime is operating at NAC-3 (set via
     set_validation_tolerance or default) AND the detail
     declares source.type='agent', the signature MUST verify
     against the registered HMAC secret. */
  if (detail.source && detail.source.type === 'agent') {
    if (!detail.source.signature) {
      return {
        ok: false,
        reason: 'agent_source_missing_signature',
        message: 'agent-sourced event must carry source.signature at NAC-3',
      };
    }
    const verified = await verify_provenance_with_registered(detail);
    if (!verified) {
      return {
        ok: false,
        reason: 'agent_source_invalid_signature',
        message: 'source.signature does not verify against registered HMAC secret',
      };
    }
  }

  // ... rest of existing checks ...
}
```

## CHANGELOG entry (v1.9.1)

**File**: `CHANGELOG.md`, insert immediately after `## [Unreleased]` and before `## [1.9.0]`:

```markdown
## [1.9.1] - 2026-05-XX

PATCH release. Closes the single substantive recommendation from
the Claude closing arbitration of v1.9 (2026-05-08): HMAC
provenance signing is now MANDATORY at NAC-3 for events with
`source.type === 'agent'`. Strict superset of v1.9.0 in plugin
contract (no plugin code change required); breaking change is to
audit pipelines that previously accepted unsigned agent events.

### Spec sec 6.2.27

- **Agent-source HMAC enforcement (REQUIRED at NAC-3, v1.9.1+)**.
  `validate_event_conformance` and `check_canonical_shape` now
  fail (severity `error` at NAC-3) when `source.type === 'agent'`
  and either `source.signature` is absent OR the signature does
  not verify against the registered HMAC secret. Closes the gap
  the v1.9 closing arbiter flagged: unsigned agent provenance was
  indistinguishable from forged.

### Runtime (`js/nac.js`)

- Bumped to `1.9.1`; `spec_version` to `1.9.1`.
- New API: `NAC.set_provenance_secret(secretOrSecrets)`. Accepts
  a string or string[]; the verifier tries each in order so per-
  deployment secret rotation works without a hot cutover.
- `check_canonical_shape` extended with two new fail reasons:
  `agent_source_missing_signature` and
  `agent_source_invalid_signature`.
- `validate_event_conformance` propagates the new reasons into
  the failure list.

### Migration impact

- **Plugin code**: NO change required. Plugins that emit events
  with `source.type === 'user'` or `source.type === 'script'`
  continue to validate. Plugins that emit events with
  `source.type === 'agent'` must add `source.signature` (use
  `NAC.sign_provenance(detail, secret)` from v1.9.0).
- **AI agents and external tools** (Computer Use, Claude.ai
  autonomous, browser-use, Talon, Voice Access, etc) that drive
  NAC-3 conformant pages MUST sign their events. Agents that
  cannot sign (e.g. testing scripts that have no secret) SHOULD
  declare `source.type === 'script'` instead of `'agent'`. The
  three-way split user/agent/script becomes load-bearing under
  v1.9.1 enforcement.
- **Hosts** must register the HMAC secret via
  `NAC.set_provenance_secret(secret)` BEFORE the first
  `validate_event_conformance` call. Hosts SHOULD source the
  secret from a server-rendered template or per-user vault;
  SHOULD NOT bake it into static JS.
- **NAC-1 and NAC-2 conformance**: signing remains OPTIONAL. The
  enforcement only activates at NAC-3 by default; can be opted
  in at NAC-2 via `set_validation_tolerance({agent_signature:'error'})`.

### Reviewer attribution

- HMAC mandatory at NAC-3: Claude (v1.9 closing arbiter).
- ProvenanceBlock authenticity enforcement: Microsoft Copilot,
  ChatGPT (v1.8 panel) -- closed via the helpers; mandatory at
  NAC-3 closes the audit pipeline gap.
```

## Open questions for Pablo

1. **Should v1.9.1 be a `PATCH` semver bump or a `MINOR`?** I'm leaning PATCH because the plugin contract is unchanged (only audit pipelines change). But arguably it tightens the NAC-3 conformance gate, which is "spec-side" -- could justify MINOR. **Recommendation**: PATCH, with the CHANGELOG making the audit pipeline impact crystal clear.

2. **Do we want NAC-3 conformance for the yujin.app/crm Patch Manager showcase to break under v1.9.1**, forcing a fix before announce? Or do we want to grandfather the showcase via a transition flag for 30 days? **Recommendation**: don't grandfather. The whole point is that the showcase IS the proof of concept. If v1.9.1 breaks it, that's the bug to fix.

3. **Multiple-secret rotation API**: the draft accepts `string | string[]`. Should it also accept a Promise-returning function for live secret rotation (e.g. JWKS-style key endpoint)? **Recommendation**: defer to v2.x. Static list of secrets is enough for v1.9.1 + v2.0 + most enterprise deployments.

4. **Should `source.type === 'script'` get the same treatment**? Scripts can also be forged. **Recommendation**: NO -- `script` is the deliberate fallback for testing tools and codemod-injected calls; mandating signing there breaks the codemod's value proposition. Only `agent` events get HMAC mandatory.

5. **Performance impact**: HMAC verification adds ~0.1-0.5ms per agent event on the receiver side. The v1.9 perf budget allows 0.5ms per `_emit`. With v1.9.1 the budget should account for verification cost on agent-heavy pages. **Recommendation**: update sec 6.2.27 perf budget to allow 1.0ms `_emit` for agent events specifically.
